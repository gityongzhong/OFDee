# 方案：合并 / 拆分 / 提取指定页 + 页面旋转

> 状态：**待拍板**。本文只做方案与可行性论证，未改动任何产品代码。
> 文中所有行号基于当前 `ui/js/*.js`。

---

## 1. 范围

| 需求 | 说明 |
|---|---|
| 提取指定页 | 从当前文档挑若干页，另存为新文件 |
| 拆分 | 每页一个文件，或按 N 页一份批量拆 |
| 合并 | 把多份文档（可跨 OFD/PDF）按序拼成一份 |
| 页面旋转 | 单页或全文档 90°/180°/270°，可逆 |

## 2. 现状盘点（代码事实）

先摸清能站在什么肩膀上，避免重复造轮子。

| 能力 | 现状 | 位置 |
|---|---|---|
| PDF 打包 | **纯光栅化**：canvas → JPEG → PDF。有损、无文字层、无书签 | `exporter.js:84` `buildPdfBlob` |
| ZIP 打包 | store 模式 + CRC32，**写档底层已具备** | `exporter.js:180` `buildZipBlob` |
| OFD 读档 | 完整（OFD.xml / Document.xml / Content.xml / 字体 / 图片） | `ofd.js:283` `parseOfd` |
| **OFD 写档** | **无**，只有解析 | — |
| **PDF 页重组** | **无**。要动 xref、对象流（ObjStm）、增量更新，自研是坑 | — |
| 旋转（PDF） | `getViewport` 未传 rotation | `pdf.js:126` |
| 旋转（OFD） | 解析时**完全没读 Rotate**；渲染产物是 SVG，外套 transform 即可 | `ofd.js:308` |

两个有利发现：

1. **PDF 旋转后文字层会自动对齐。** 文字层和画布共用同一个 `vp`
   （`pdf.js:186` 与 `pdf.js:200`），只要 `getViewport` 带上 rotation，
   pdf.js 自己会把每个 `<span>` 排到旋转后的位置 —— 不需要额外算坐标变换。
2. **OFD 写档的底座已经有一半。** `buildZipBlob` + `crc32` + `dosDateTime` 都在，
   缺的是 XML 生成逻辑，而不是打包器。

## 3. 核心决策：产物质量路线

这是本方案**唯一需要你拍板**的问题，其余都是工程量。

### 路线 A：全光栅化（零新依赖）

所有操作统一走「取页 → 渲染位图 → `buildPdfBlob` 打包」。

- 优点：代码量最小（主要工作量是页选择 UI）；跨格式混合并无障碍，因为位图是公共中间层
- 缺点：产物是**扫描版** —— 文字层丢失、Ctrl+F 搜不到、每页一张 JPEG 体积大、放大发虚
- 产物体积估算：12 页 A4 @ 2 倍分辨率 ≈ 8～15 MB

### 路线 B：原生重组（保真）

- PDF → PDF：引入 `pdf-lib`（MIT，约 400 KB min），`copyPages` 重组，
  完整保留文字层、矢量、书签
- OFD → OFD：自研写档，从源 ZIP 拷 `Content.xml` 与资源，重建 `OFD.xml` / `Document.xml`
- 优点：无损、体积小、文字仍可选可搜
- 缺点：两种格式各要一套实现；跨格式混合并**仍要退回光栅化**；新增一个依赖

### 路线 C：分场景混合（推荐）

- 页选择 UI 与执行器解耦，先算出「页序列」`[{docRef, pageIndex, rotation}]`，
  再由执行器按场景选落地方式
- 若源**全是 PDF 且未跨格式** → 走 `pdf-lib` 无损重组
- 其余（含 OFD、跨格式、旋转过的）→ 光栅化
- 旋转优先做**视图层**（不改文件），落盘时才决定写入方式

### 对比

|  | 路线 A 光栅化 | 路线 B 原生 | 路线 C 混合 |
|---|---|---|---|
| 新增依赖 | 无 | pdf-lib | pdf-lib（可选） |
| 文字层 | 丢失 | 保留 | PDF→PDF 保留 |
| 跨格式并 | 支持 | 不支持 | 部分 |
| 体积 | 大 | 小 | PDF 小 / 其余大 |
| 工程量 | 小 | 大 | 中 |

**建议：第一版走路线 A，但按路线 C 的接口设计。**
理由：报销归档这类主力场景本来就是给财务看的，不需要文字层；
先把页选择 UI 和「页序列 → 产物」的执行器骨架立住，
后面想升级保真度，只换执行器，UI 不用动。

> 若你要求「合并后的 PDF 必须能搜、能选字」，那就必须走 B/C 并引入 pdf-lib，
> 与「克制不加依赖」的既有约束冲突，需要你明确取舍。

## 4. 页面旋转设计

分两层，**先做视图层**。

### 4.1 视图旋转（临时，不落盘）

- PDF：`getViewport({ scale, rotation: (p.rotate + extra) % 360 })`，
  文字层共用同一 `vp` 自动跟随
- OFD：页面 SVG 外层套 `transform="rotate(θ, cx, cy)"`，并交换 `pageW/pageH`
- 作用域：当前页 / 全部页 / 当前选中页，右键菜单与工具栏各给入口
- 状态：`state.rotation = Map<pageIndex, 0|90|180|270>`，随标签快照走

**贯通点（改动面比想象大，别低估）**：
`pageSize()`、`rowWidthMM()`、`rowHeightMM()`、缩略图渲染、
双页对开的配对逻辑（`state.spread` 下 `idx -= idx % 2`）、
适应宽度的 `stageAvail()`、文字层高度。
凡是读 `pageW/pageH` 的地方都要走「旋转后的等效尺寸」。

### 4.2 落盘旋转（持久）

导出时按路线决定：

- PDF：写页字典 `/Rotate`（原生路线由 `pdf-lib` 的 `setRotation` 完成）
- OFD：写 `<Page><Area><Rotate>`，或直接在光栅化时转 90°
- 光栅化路线最简单：渲染完 canvas 后 `ctx.rotate` 再打包

## 6. 数据结构与代码骨架

统一的「页序列」是路线 A/B/C 的公共契约 —— 先把这一层定死：

```js
/** 一次操作的目标：跨文档、跨格式、带旋转的页序列 */
// PageRef = { tabId, kind: 'ofd'|'pdf', pageIndex: number, rotation: 0|90|180|270 }
// Plan    = { pages: PageRef[], outFormat: 'pdf'|'pngZip', quality: number }

/** 执行器：把页序列渲染成产物。路线 A/B 只换这里 */
async function executePlan(plan, onProgress) {
  const canvases = [];
  for (const [i, ref] of plan.pages.entries()) {
    const c = await renderRefToCanvas(ref);   // 内部处理 rotation
    canvases.push({ canvas: c, wMM: ..., hMM: ... });
    onProgress((i + 1) / plan.pages.length);
  }
  return buildPdfBlob(canvases, { quality: plan.quality });
}
```

产物落盘复用现有的原生「另存为」通道（`save_file` + base64 过 IPC）。
注意：大产物走 base64 会翻倍内存，见 §7 风险 2。

OFD 写档（仅路线 B 需要）的关键点：

- 页面尺寸不一致时，OFD 的 `<Page>` 可带 `<Area><PhysicalBox>` 覆盖
  `CommonData` 的 `PageArea`，所以 A4 与发票（210×140）可以并进同一份
- **资源 ID 必须重映射**：多文档合并时两边字体 ID 都从 1 开始会撞。
  做法：`DOMParser` 解析 `Content.xml` → 建 ID 映射表 → 改写 `FontID` /
  `ResourceID` 属性 → `XMLSerializer` 回写

## 7. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | 光栅化产物体积大（12 页可达 10 MB+） | JPEG 质量降到 0.85；面板上给出体积预估 |
| 2 | 大产物走 base64 过 IPC 内存翻倍 | 可在 Rust 侧加临时文件中转命令，绕开 base64 |
| 3 | 旋转后布局计算没贯通，双页对开/缩略图错位 | 抽 `effectiveSize(pageIndex)` 单一入口，禁止散读 `pageW/pageH` |
| 4 | 合并 100 页要渲染 100 次，卡顿 | 分片 + `requestAnimationFrame` 让出主线程，进度条可见 |
| 5 | OFD 写档后别的阅读器打不开 | 先用样本文件做交叉验证；第一版不碰 OFD 写档可完全规避 |

## 8. 实施顺序建议

| 阶段 | 内容 | 依赖 |
|---|---|---|
| S1 | 页选择面板 + 提取所选（光栅化） | 无 |
| S2 | 拆分（每页 / 每 N 页） | S1 |
| S3 | 合并对话框（跨标签、可排序） | S1 |
| S4 | 视图层旋转 + 落盘时生效 | 单做也行，建议 S1 之后 |

旋转（S4）与提取/拆分（S1-S3）相对独立，可以调换顺序。
若你更在意扫描件纠偏，可以先做 S4。
